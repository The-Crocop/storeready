CLOUD PLATFORM

StoreReady Cloud

Cloud adds release memory to the local scanner: GitHub sign-in, workspaces, projects, revocable CI tokens, release history and approved baselines.

First-run setup

  1. Sign in with GitHub.
  2. Create a StoreReady workspace.
  3. Create a project with a stable project key, for example mobile-app.
  4. Generate a CI token for that project.
  5. Copy the token immediately. StoreReady only stores its hash and will not show the full secret again.
  6. Save the token in your CI secret store.
Project scoped: a CI token can only read and write scan/baseline data for the project that created it. Tokens can be revoked independently.

The artifact stays local

StoreReady scans the IPA/AAB on the developer machine or CI runner. Cloud receives normalized release metadata rather than the application binary.

Configure the CLI

export STOREREADY_CLOUD_URL=https://your-cloud.example
export STOREREADY_API_KEY=srp_...

storeready push \
  --project mobile-app \
  MyApp-2.4.0.ipa

Approve a store release

After Apple or Google approves an exact release artifact, record it as the project/platform baseline:

storeready approve \
  --project mobile-app \
  MyApp-2.3.0.ipa

The next push automatically fetches that approved baseline and applies the privacy-sensitive diff locally before uploading the normalized result.

What is currently sent

  • Artifact filename and SHA-256
  • Platform
  • Passed / warning / blocker counts
  • Detected privacy-sensitive permission signals
  • Detected SDK signals

What is not currently sent

  • The IPA or AAB binary
  • Your application source code
  • Signing certificates or provisioning keys
