Getting started

StorePreflight scans the final release artifact before it reaches Apple or Google. Start locally, then add it to CI.

Requirements

To build the CLI from source you need Go 1.23 or newer. A scan itself only needs the final .ipa or .aab artifact.

Build the CLI

git clone https://github.com/The-Crocop/storepreflight.git
cd storepreflight
go build -o storepreflight ./cmd/storepreflight

./storepreflight version
Release binaries are planned. Tagged releases already use GoReleaser for macOS, Linux and Windows builds.

Run your first scan

./storepreflight scan MyApp.ipa

# or
./storepreflight scan app-release.aab

A blocker returns exit code 2. Warnings are informational by default, which makes the initial rollout safe for existing CI pipelines.

Fail CI on warnings

storepreflight scan --fail-on-warning MyApp.ipa

With --fail-on-warning, warnings return exit code 1. Use this after your team has reviewed and accepted the rule set.

Compare with an approved release

For a completely local workflow, create a baseline from an already-approved artifact:

storepreflight baseline MyApp-2.3.0.ipa

storepreflight scan \
  --baseline storepreflight-baseline.json \
  MyApp-2.4.0.ipa

StorePreflight flags newly observed privacy-sensitive permissions and SDK signals relative to that baseline.

Use machine-readable output

storepreflight scan --format json MyApp.ipa
storepreflight scan --format markdown MyApp.ipa
storepreflight scan --format sarif MyApp.ipa

Supported formats are text, json, markdown and sarif.
