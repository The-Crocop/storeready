CI/CD

GitHub Action

Run StorePreflight immediately after your release artifact is built. The report appears in the workflow summary and uses CI-friendly exit codes.

Local-only preflight

name: Mobile release preflight

on:
  pull_request:
  workflow_dispatch:

jobs:
  storepreflight:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5

      # Produce/download the final IPA or AAB first.

      - uses: The-Crocop/storepreflight@main
        with:
          artifact: build/MyApp.ipa

Use a repository baseline

- uses: The-Crocop/storepreflight@main
  with:
    artifact: build/MyApp.ipa
    baseline: .storepreflight/approved.json
    fail-on-warning: "true"

Cloud-backed release history

Create a project in StorePreflight Cloud and generate a CI token. Store it as a GitHub Actions secret such as STOREPREFLIGHT_API_KEY.

- uses: The-Crocop/storepreflight@main
  with:
    artifact: build/MyApp.ipa
    project: mobile-app
    cloud-url: https://your-cloud.example
    api-key: ${{ secrets.STOREPREFLIGHT_API_KEY }}

When project is configured, the action uses storepreflight push. The IPA/AAB remains on the runner. StorePreflight Cloud receives only normalized release metadata.

Secret handling: each spf_ token is scoped to one StorePreflight project, stored server-side only as a SHA-256 hash, and can be revoked without affecting other projects.

Inputs

InputRequiredDescription
artifactYesPath to the final IPA or AAB.
baselineNoLocal approved-release baseline JSON.
fail-on-warningNoFail with exit code 1 when warnings exist.
projectNoCloud project key. Enables Cloud history.
cloud-urlWith projectYour StorePreflight Cloud base URL.
api-keyWith projectThe project's spf_ CI token.

Pin releases

During early development, examples use @main. Once StorePreflight v1 is released, production workflows should pin a stable major or exact tag.
