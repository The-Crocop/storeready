WHY STOREREADY

A release diff, not another checklist.

Static linting is useful. The bigger risk is what changed since the release Apple or Google already accepted.

01

Scan the final artifact

Inspect the IPA or AAB that will actually be submitted, not a source-tree approximation.

02

Mark the approved release

When a store approves a build, StoreReady records its privacy-sensitive baseline.

03

Catch risky drift

New permissions and SDK signals are highlighted automatically on the next release.

OPEN SOURCE CLI

Useful before you create an account.

Run StoreReady locally, in GitHub Actions, or in any CI environment. Generate terminal, JSON, Markdown or SARIF output.

Explore CLI commands →
Shell
# Scan locally
storeready scan MyApp.ipa

# Create a local baseline
storeready baseline MyApp-2.3.0.ipa

# Compare the next release
storeready scan \
  --baseline storeready-baseline.json \
  MyApp-2.4.0.ipa
GitHub Actions
- uses: The-Crocop/storeready@main
  with:
    artifact: build/MyApp.ipa
    project: mobile-app
    cloud-url: https://app.storeready.dev
    api-key: ${{ secrets.STOREREADY_API_KEY }}
