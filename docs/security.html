TRUST

Security

StoreReady is designed around local artifact inspection, minimal Cloud data and project-scoped automation credentials.

Local-first scanning

The open-source CLI inspects IPA/AAB artifacts locally. Cloud-enabled workflows send normalized findings rather than the application binary.

Human authentication

StoreReady Cloud uses GitHub OAuth for human sign-in. Browser state-changing requests use CSRF protection and the dashboard/API are designed to share one public origin.

CI tokens

CI credentials use the srp_ prefix and are scoped to a single StoreReady project. New tokens are generated from 256 bits of cryptographic randomness. The full token is shown once; Cloud persists a SHA-256 hash and a short display prefix instead of the raw secret. Tokens record last use and can be revoked individually.

Secrets

Store project tokens in your CI secret manager. Do not commit StoreReady tokens, signing certificates, App Store credentials or Google Play credentials to source control.

Infrastructure

Production configuration is designed for HTTPS, secure session cookies, PostgreSQL and a container runtime. The development/bootstrap API key is disabled by default and is not intended for production.

Responsible disclosure

If you discover a vulnerability, please avoid opening a public issue containing exploit details. Contact the project maintainer privately through the contact information associated with the GitHub repository.

Build checks

The CLI is built and tested on Linux and macOS. StoreReady Cloud validates backend tests, Spring AOT compatibility, Angular production builds and its production container build in GitHub Actions.
